The `set_player` method is currently only called on the server. Since the `Player` scenes (`BOTINI_SCENE` and `BOSS_SCENE`) were removed from the global `PlayerSpawner` in `game.tscn`, they will not be automatically instantiated on clients. Furthermore, the `synchronizer.root_path` is set locally on the server and is not replicated to clients. 

This means clients will have a `MultiplayerClient` node but no `Player` child, and their `MultiplayerSynchronizer` will be looking for properties on a non-existent node, breaking multiplayer synchronization. 

To fix this, you should either:
1. Add a `MultiplayerSpawner` to the `MultiplayerClient` scene configured to spawn the player scenes.
2. Use a replicated variable (e.g., `player_type`) with a setter that instantiates the correct player scene on all peers.

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

When replacing an existing player, calling `queue_free()` is not sufficient to avoid name collisions in the same frame because `queue_free()` is deferred. If a new player node is added immediately after (as happens in `PlayerManager.spawn_round_players`), Godot will detect a name collision and rename the new node (e.g., to `123@2`). This breaks multiplayer synchronization which relies on consistent node paths.

You should explicitly remove the child from the tree before calling `queue_free()`.

```
	if is_instance_valid(player):
		remove_child(player)
		player.queue_free()
		player = null
```

	var client: MultiplayerClient = players.get(owner_id)

		return
